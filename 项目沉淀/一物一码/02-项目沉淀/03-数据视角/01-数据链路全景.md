# 01-数据链路全景

> 一物一码数据从业务系统到看板的全链路映射
>
> 📌 2026-07-28 v2 更新：基于 **指标PRD V1.1**（45,000字）大幅升级指标定义和数据结构

---

## 核心架构原则

| 原则 | 说明 |
|:----|:-----|
| **售卖独立** | 售卖量按 RTD 订单商品统计，与 `activity_no` **不关联**——商品售卖与活动效果之间不存在直接归因关系 |
| **活动流量独立** | 曝光、参与、活动中奖只在活动层统计，**不向奖品层归因** |
| **双中奖口径** | 活动级中奖取 `hit_result=3`；奖品级中奖直接按 `record_user_line` 统计 |
| **两层获得方式** | 基础取 `prize_grant_mode`，膨胀取 `prize_expand_mode` |
| **不可直接加总** | 活动总量不得由奖品路径行求和；人数跨奖品、跨路径必须重新去重 |
| **自然时间** | 各指标使用自身业务发生时间，归属 `dt` 和 `time_slice_10min`（10分钟时间分片） |

---

## 交付物范围

**本期范围：23 项 P0 指标**

| 分组 | 指标数 | 说明 |
|:----|:-----:|:----|
| 🛒 商品售卖 | 3 | 全渠道/线上/线下 RTD 售卖量 |
| 📈 活动流量与转化 | 7 | 曝光、参与、中奖、参与率、中奖率 |
| 🎁 奖品路径 | 9 | 加C、复购、膨胀、直接选择等 |
| 💰 奖励发放 | 4 | 发放人数/次数/率、现金红包费用 |

**不在本期范围：** 订单复购归因、核销、券费用、新老用户

**交付物：** 3类明细模型 + 2张应用层表

## 数据源

### 表清单

| 表名 | 用途 |
|:----|:-----|
| `t_rtd_cap_activity` | 活动配置：通过 `activity_no` 识别瓶内码活动 |
| `participate_log` | 参与流水：`hit_result IN (2,3)` 计参与，`=3` 计中奖 |
| `record_user_line` | 用户中奖记录：核心主表，关联奖品配置 |
| `activity_prize` | 活动奖品配置表：`id = record_user_line.prize_row_id` |
| `expand_option` | 膨胀配置表：`record_user_line.expand_option_id = expand_option.id` |
| `customer_add_log` | 加C事件流水 |
| `repurchase_log` | 复购第二瓶扫码流水 |
| `dwd_order_rtd_item_di` | RTD 商品售卖订单 |
| `dws_order_rtd_sales_di` | 交易汇总表（复用，不新建） |

### 核心关联关系

```
活动流量层
  participate_log ──→ 曝光/参与/中奖
        │
        ▼
奖品路径层
  record_user_line ──→ activity_prize（基础奖品）
        │               expand_option（膨胀奖品）
        │               prize_grant_mode（获得方式）
        ▼
行为事件层
  customer_add_log（加C） ←→ record_user_line
  repurchase_log（复购）
  direct_select（直接领）
```

## 明细模型（3类）

| 模型 | 说明 |
|:----|:-----|
| **曝光会员10分钟轻明细** | 活动曝光数据，按10分钟分片，唯一会员去重 |
| **参与中奖履约明细** | 参与 + 中奖 + 奖品履约全链路，核心宽表 |
| **实际加C会员10分钟轻明细** | 加C行为数据，按10分钟分片 |

| **奖励履约表** | 奖品级指标聚合：加C/复购/膨胀/发放 |

## 23项P0指标完整定义

### 🛒 商品售卖（3项）

| 指标 | 口径 | 数据源 |
|:----|:----|:------|
| 全渠道售卖量（线上+线下） | `SUM(spec_num)`，范围线上∪线下 | `dwd_order_rtd_item_di` |
| 全渠道售卖量（线上） | `SUM(spec_num)`，范围线上渠道 | 同上，渠道过滤 |
| 全渠道售卖量（线下） | `SUM(spec_num)`，范围线下渠道 | 同上，渠道过滤 |

### 📈 活动流量与转化（7项）

| 指标 | 口径 | 说明 |
|:----|:----|:-----|
| **活动曝光人数** | 触发活动页埋点的唯一 member_id 数 | 从埋点提取，不下钻到单奖品 |
| **活动参与人数** | `participate_log.hit_result IN (2,3)`，member_id 去重 | 未登录/未授权不纳入 |
| **活动人均参与次数** | 参与次数÷参与人数 | |
| **活动参与率** | 参与人数÷曝光人数 | |
| **中奖人数** | `participate_log.hit_result=3`，member_id 去重 | 活动级口径 |
| **中奖次数** | `hit_result=3` 的记录数 | |
| **中奖率** | 活动中奖人数÷活动参与人数 | 按实际值展示，不设100%预期 |

### 🎁 奖品路径（9项）

| 指标 | 口径 | 说明 |
|:----|:----|:-----|
| **实际加C人数** | 完成加C行为的唯一 member_id | 以用户最终选择的奖品为准 |
| **实际加C人次** | 加C行为记录数 | 同一用户多次计数 |
| **加C领取路径履约率** | 加C领取人数÷中奖人数 | |
| **复购第二瓶人数** | 完成复购扫码的唯一 member_id | |
| **复购第二瓶次数** | 复购扫码记录数 | |
| **奖品膨胀人数** | 选择膨胀奖品的唯一 member_id | |
| **直接选择人数** | 直接领取（非膨胀）的唯一 member_id | |
| **首次奖品膨胀人数** | 首次即选择膨胀的用户数 | |
| **首次直接选择人数** | 首次即直接领取的用户数 | |

### 💰 奖励发放（4项）

| 指标 | 口径 | 说明 |
|:----|:----|:-----|
| **现金红包费用** | 微信商户号实际发放金额 | 优先以到账数据为准 |
| **奖品发放人数** | 完成发放的唯一 member_id | 以用户完成获取动作为准 |
| **奖品发放次数** | 发放记录数 | |
| **奖品发放率** | 发放人数÷中奖人数 | |

## 统计筛选维度

| 维度 | 层级 | 说明 |
|:----|:----|:-----|
| 活动 | 1 | 通过 `activity_no` 识别，支持跨活动 |
| 奖品 | 2 | 与活动强关联 |
| 获得方式 | 3 | `DIRECT` / `PRIVATE_DOMAIN`(加C) / `REPURCHASE`(复购) |
| 膨胀 | 4 | 仅膨胀奖品有配置时显示 |

## 数据建设三阶段规划

> 来源：PRD 出发点的业务规划（2026-07-28 刘晋泽确认）

| 阶段 | 内容 | 产出 |
|:----|:----|:----|
| **Phase 1** | 按基础指标构建明细宽表 → 跑SQL验证 | 3类明细模型：曝光、参与中奖履约、加C |
| **Phase 2** | 宽表逻辑验证无误后固化看板 | 2张应用层表：活动效果 + 奖励履约 |
| **Phase 3** | 扩充基础指标 → 增加跨表、跨业务指标 | 完整指标体系 |
