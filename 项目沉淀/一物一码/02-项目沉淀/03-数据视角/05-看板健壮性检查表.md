# 05-看板健壮性检查表

> 📌 基于 V26.4.1 技术方案中的故障防控规范补充（2026-07-29）
>
> 业务系统发版或字段变更时，数据同学应该逐项检查的清单。
> 目标：把「看板崩了」从被动发现变成主动预防。

## 发版前检查清单

- [ ] 确认本次发版涉及的字段变更
- [ ] 对照 [[字段映射清单]] 检查受影响的数仓表
- [ ] 检查 ETL 脚本是否需要同步修改
- [ ] 检查 DWD/DWS 层依赖关系是否断裂
- [ ] 在测试环境跑一遍受影响的看板SQL
- [ ] 与预期值对比，确认无异常

## 发版后监控清单

- [ ] 观察看板数据（连续3天）
- [ ] 核对关键指标（扫码量、中奖量、红包发放量）
- [ ] 检查异常告警是否触发
- [ ] 如有异常，对照 [[断链事故记录]] 排查
- [ ] 监控 `PAY_RETRY_COUNT` 趋势（支付失败率预警线）

## 核心指标监控（必须设告警）

| 指标 | 告警触发条件 | 严重级别 | 说明 |
|:----|:-----------|:--------|:----|
| **扫码量** | 日扫码量骤降 > 50% | P0 | 可能入口挂了 |
| **中奖率** | 中奖率归零 | P0 | 可能库存配错或概率公式异常 |
| **支付失败率** | > 5%（超过预期） | P1 | `pay_retry_count` 激增，微信支付异常 |
| **断链** | 某层级通过率为 100% 或 0% | P1 | 可能代码逻辑跳过了校验 |
| **空值率突变** | 关键字段空值率从 <5% 突增到 >50% | P0 | 可能字段被改或 ETL 挂了 |
| **数据量异常** | 日增量 < 平日 20% 或 > 平日 300% | P1 | 刷数据或数据丢失 |

## API 层规范（技术方案要求）

故障防控手册要求：

| 规范 | 要求 |
|:----|:----|
| **限流** | API 层默认配置 sentinel 限流熔断 |
| **熔断** | 上下游依赖链路同量级限流策略 |
| **参数校验** | 零信任原则，后端校验所有前端参数 |
| **跨单元调用** | 在 RPC 模块说明 |
| **跨业务域依赖** | 注明非预期依赖 |

这些规范如果没落地，看板数据可能因上游限流熔断出现异常缺口。

## 看板自愈机制

- [ ] 字段缺失检测：ODS 层字段名与预期不符时告警
- [ ] 空值率突变检测：某字段空值率从 1% 突增到 100%
- [ ] 数据量突变检测：日增量骤降或骤升
- [ ] `layer_break_code` 分布异常检测：某层级拦截占比突变为 0% 或 100%
- [ ] `pay_retry_count` 趋势监控：连续上涨超过阈值告警
