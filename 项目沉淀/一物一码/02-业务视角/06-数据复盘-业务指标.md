# 06-数据复盘（业务指标）

> 📌 基于 V26.4.1 技术方案中的业务指标影响表整理（2026-07-29 补充）
>
> ⏳ 实际数据待项目上线后填充

## 影响指标全景

| 业务线 | 子类 | 核心指标 | 说明 |
|:------|:----|:--------|:----|
| **交易线** | 咖啡交易 | 订单下单/支付/完成/退款/取消、三方咖啡交易、转换类（升杯/算价） | 核心交易链路，码扫码后的购买行为 |
| | 卡券交易 | 库券/次卡、三方卡券、虚拟订单 | 膨胀券/优惠券的使用场景 |
| | 用户商品 | 会员注册、会员卡、会员登录 | 首扫时需要用户注册/登录 |
| **营销线** | 站外营销 | 微信攒授权、支付宝攒授权、加C | 扫码前需要用户授权 |
| | 站内营销 | 发券活动参与次数/人数/成功率、抽奖活动资格校验通过比率/中奖率、拉新活动参与次数/成功率 | 抽奖核心链路 |
| | 营销策略 | 优惠券发放量/核销量、分补贴类型发放量/核销量、首页弹窗/支付完成弹窗/菜单弹窗分策略曝光数与流量占比 | 膨胀券发放和使用 |

## 关键埋点字段

从领域模型和流程图看，以下字段直接对应看板指标：

| 埋点位置 | 字段 | 对应指标 | 数据源表 |
|:--------|:----|:--------|:--------|
| 扫码 | `PARTICIPATE_LOG.participate_phase` | 首扫量/复扫量 | 参与日志表 |
| 拦截 | `PARTICIPATE_LOG.layer_break_code` | 各层级拦截率 → **7级漏斗** | 参与日志表 |
| 中奖 | `USER_RECORD_LINE.record_prize_status` | 中奖率、待选/发放/膨胀比例 | 用户中奖记录表 |
| 支付 | `USER_INSTANCE.instance_status` | 打款成功率 | 现金发放实例表 |
| 重试 | `USER_INSTANCE.pay_retry_count` | 支付失败重试率 | 现金发放实例表 |
| 核销 | 父订单编号 | 膨胀券核销率 | — |

## 7级拦截漏斗（数据看板核心）

```
                    进入抽奖  (100%)
                       ↓
  L1  位置授权校验  →  通过率  (A%)
                       ↓
  L2  活动总库存    →  通过率  (B%)
                       ↓
  L3  时段库存      →  通过率  (C%)
                       ↓
  L4  个人上限      →  通过率  (D%)
                       ↓
  L5  新用户判定    →  新用户直中  (E%)
                       ↓
  L6  城市库存      →  通过率  (F%)
                       ↓
  L7  概率计算      →  中奖率    (G%)
```

**数据来源：** `PARTICIPATE_LOG.layer_break_code` 字段记录了用户在哪一级拦截失败。

## 预期指标参考

| 指标 | 预期值 | 数据来源说明 |
|:----|:------|:-----------|
| 扫码率 | （待定） | 投放量 / 扫码量 |
| 中奖率 | 取决于库存和概率公式 | `(城市奖品总量-已中奖)/(城市产品总量-已扫码/预估扫码率)` |
| 复购率 | （待定） | 中奖用户中完成第二瓶扫码的比例 |
| 红包到账率 | （待定） | `(50已到账) / (20待复购)` |
| 膨胀券核销率 | （待定） | `(60已使用) / (30待使用)` |
| 支付失败率 | （目标 < 1%） | `pay_retry_count > 0` 的比例 |
