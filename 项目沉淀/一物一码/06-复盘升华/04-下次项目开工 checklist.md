# 04-下次项目开工 checklist

> **用法**：新项目开工就打开这页，按阶段逐项勾。每项后面的 `#号` 指向 [[一物一码/06-复盘升华/01-方法论沉淀\|方法论沉淀]] 对应条目的完整理由与证据。
> 标 ⭐ 的是本项目**吃过亏**的项，优先核对。

## 🚦 Gate 0 · 立项

- [ ] ⭐ 产出「**唯一北极星 + 2 个约束指标**」决议单并**签字**（`#12`）
- [ ] ⭐ 北极星未签字前，**不动**奖项比例与包装设计（`#12`）
- [ ] ⭐ 明确「**谁对收益负责谁主导**」——由运营/业务主导，技术/产品是约束方（`#27`）
- [ ] ⭐ 立项第一页：**配合方清单 + 交叉约束图**（本项目＝品牌/财务/法务/技术/数据/供应链/电商 7 方向）（`#29`）
- [ ] ⭐ 拿「配合方清单 + 交叉约束」换**授权**：定核心负责人 + 各视角子负责人（`#10`/`#29`）
- [ ] 子负责人选型＝**懂本职能 + 懂交叉约束**（如财务线要懂系统入账）（`#10`）
- [ ] 立项会必到：**财务 / 品牌 / 商业分析**（法务/数据/供应链本就该在）（`#11`）
- [ ] 立项会必答：**会不会发生费用？口径与归属是谁？**（`#11`）
- [ ] 多方案评审用**同一张多维对比表**（同口径/参数/周期），无数字不进决策会（`#13`）

## 💰 Gate 1 · 方案与预算

- [ ] ⭐ 预算评审：财务确认「**怎么入账**」（记账口径/税负/结算周期）（`#11`）
- [ ] ⭐ 处罚表三列：**面值 / 物料成本 / 履约成本**；面值 < 成本不进奖池（`#16`）
- [ ] 膨胀玩法**单独验算**膨胀后档位的价值闭环（`#16`）
- [ ] 税负敏感度一页：先锚**免税临界点**，再排奖项档位；预算表拆「面值 + 税负」两行（`#15`）
- [ ] 中奖率列为**可调项清单**（含各档区间）；锁总额后反推分档（`#14`）
- [ ] 成本压降写明「**谁提的 + 目标 + 靠哪几个参数**」（`#28`）
- [ ] 核心玩法逐条附 **AB 实验设计**（变量/假设/主指标/最小样本/窗口）（`#35`）
- [ ] 每个预估参数标「**来源 + 置信度**」，低置信度先给区间 + 小样测试（`#36`）
- [ ] 需求「完成定义」＝**本模块目标指标 + 埋点清单**，未填不许排期（`#18`）
- [ ] **规则定稿 + 法务通过**设为上线前置硬节点（进甘特图）（`#19`）
- [ ] 用户可见规则写明「**规则锁定期 + 变更条款**」（`#19`）
- [ ] 活动规则**只写截止日**，不锁定开始时间（`#22`）
- [ ] 链路/码数量：**能否用 1 个码 / 1 条主链路**承载全部玩法（`#17`）

## 🗓️ Gate 2 · 排期与开发

- [ ] ⭐ 上线日唯一基准＝**包装 / 产线 / 入仓时间表**，技术侧倒排（`#21`）
- [ ] 包装定稿设独立里程碑并**冻结**（含工厂清单）；变更走变更单 + 重排审稿缓冲（`#20`）
- [ ] ⭐ 方案定稿：数据 + 财务确认「**数据能不能进财务系统**」（接口/字段/交付层级）（`#11`）
- [ ] 提数模板三栏填全：**源表清单 / 交付层级（业务可用层）/ 口径负责人**（`#26`）
- [ ] 业务先交**可跑 SQL 原型** + 逻辑说明，会上只对差异点（`#32`）
- [ ] 上线初期交付物＝**宽表 + SQL 定稿**；看板放到口径冻结之后（`#31`）
- [ ] 抽奖次数发放节点＝**订单完成**；「完成即退」设风控观察指标（`#25`）
- [ ] 财务字段缺失分「阻塞/非阻塞」；非阻塞可业务先行，但**当场写明临时对账口径**（`#11` 补充）
- [ ] 券配置表增「**财务入账金额**」列，由财务复核（`#34`）
- [ ] 艺人物料上关键路径：**配置冻结 → 规则校准 → 提审**（串行里程碑）（`#23`）

## 🚀 Gate 3 · 上线前

- [ ] ⭐ **异常/边界场景清单**逐项挂负责人与验收时间：重复扫 / 频次上限 / 设备去重 / 老用户 / 扫不出码兜底（`#24`）
- [ ] 所有**状态样式统一收口**评审（可点击按钮 vs 状态展示）（`#24`）
- [ ] 风险清单加权重列：**不可逆 / 涉外 / 可降级**；涉外项配 B 方案 + 触发条件 + 拍板人（`#2`）
- [ ] 值守排班 + **6h 一轮战报模板** + 矛盾识别法（业务安静 vs 技术群新风险）（`#3`）
- [ ] 接口异常**先对照「码状态台账」**归因（是否已赋码/入仓/上架），再决定是否风控拦截（附录 J）
- [ ] 内测第一天建**结构化问题表**（模块/现象/截图/负责人/状态），群公告只放链接（附录 E）
- [ ] 内测券**一眼可辨为测试** + 「测试奖 vs 正式奖」对照说明置顶（附录 F）
- [ ] 用规则里的概率算一张「**期望人数表**」，再判定"异常"（`#5`）
- [ ] 核对宣传语与中奖率的**数量级落差**（期待管理 + 合规）（`#5`）

## 📈 Gate 4 · 上线后

- [ ] ⭐ 每天看**领取率**（发放÷中奖），不只看总量（`#4`）
- [ ] 领取率上线即定**目标值** + 开 A/B（提示时效 / 动作前置 / 失败重试）（`#4`）
- [ ] 归因第一步：**供给 vs 需求**（对比铺货/出库节点、周末效应）（`#6`）
- [ ] 每个「率」写清**分子分母 / 去重粒度 / 时间窗 / 数据源**；跨表先出**口径表**（`#7`）
- [ ] 成本只用「**结算单价**」一个口径（先找财务要单张记账价）（`#8`）
- [ ] 跨团队卡点：**一笔真实样本走通全链路** + 明确责任方 + 写死期限（`#9`）
- [ ] 配置变更写**变更日志**并抄送拍板人确认（`#33`）
- [ ] 对外/对上文档首屏＝**结论 3 条 / 待你决策项 / 需要你的时间点**（`#30`）
- [ ] 业务系统发版时跑一遍 [[一物一码/04-数据视角/05-看板健壮性检查表\|看板健壮性检查表]]（`#7`）
