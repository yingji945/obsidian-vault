## 2. 即享瓶内营销码活动统计对齐会

| 项目 | 内容 |
|:----|:-----|
| 📄 文档编号 | #7 |
| 🕐 时间 | 15:06~17:10（2小时！最详实）|
| 👥 参会人 | 刘晋泽/蔡鸿东/麻孜凯/苏航 |

### 核心内容

📊 **数据方案定稿会**（2026-08 回填：口径细节全量补齐）

- 筛选层级：**活动→奖品→获取方式→是否膨胀**（固定联动）
- 获取方式：加C / 第二瓶复购 / 直接领取（三类互斥）
- 膨胀逻辑：独立实体配置，用户可在原奖品与膨胀奖品中二选一
- 核心漏斗：**曝光→参与→中奖→选择奖品→完成发放**
- 数据源：`record_user_line`主表+奖品配置+膨胀配置+扫码流水
- 落地策略：先搭**Hive宽表**+SQL跑数，暂不做固化看板
- 蔡鸿东已完成第一版测试跑数，数据符合预期
- **7月底前完成全量校验**

#### ① 筛选维度属性

- 所有筛选维度**默认全选、支持多选复选**，暂不做强制单选限制（后续再评估）
- **联动规则**：选择上层维度后，下层仅展示对应范围内的可选项，避免无效选项
- 活动维度：覆盖后台**所有已配置**的瓶内营销码活动，支持**跨活动批量筛选与聚合**
- 奖品维度：与所属活动**强关联**，仅展示当前活动下已配置奖品行，**无跨活动统一奖品池**
- 获取方式：与 **4 类券类型无绑定关系**，支持任意组合；加 C 类奖品需上传渠道码图片，直接领取/复购类无强制上传要求
- 膨胀维度：为奖品的**可选配置项**，仅当奖品已配置膨胀时展示，无配置则自动隐藏
- 报表结构：参考现有业务汇报模板，**活动级汇总 + 单奖品明细两层**

#### ② 数据来源与关联键

- 🔑 **活动标识**：埋点上报的 `activity number` 对应**后台活动ID**（非单奖品行ID）；**活动级曝光直接从埋点层提取**
- 🔑 **状态字段**：中奖记录状态**仅保留 1/2/3，状态 4（作废）直接排除**，不纳入任何统计口径
- 🔑 **获取方式字段**：直接取中奖记录 `price_grant_mode`，以用户**最终选择的实际奖品**配置为准
- 主表：`record_user_line`（用户中奖记录，覆盖中奖后全链路行为）+ 关联活动奖品配置表 / 独立膨胀配置表 / 扫码流水表
- 关联键：奖品行ID → 活动奖品配置表；`expand_option_id` → 膨胀配置表

#### ③ 参与人数口径（关键边界）

- **待选状态**（中奖后未做选择）**统一纳入**活动参与人数统计，不单独排除
- **未登录授权**用户**不纳入**活动参与人数，**仅在扫码流水表中记录**
- **非中奖数据**（风控拦截、未登录导致的非中奖扫码）**从扫码流水表提取**，补充活动级统计的**分母数据**

#### ④ 指标定义

- **曝光**：仅支持**活动维度聚合**（所有触发活动页埋点的独立用户数）；**不支持下钻单奖品**（前端埋点未上报单奖品点击）
- **中奖口径**：当前为 **100% 中奖** → 活动参与人数与中奖人数**暂为等值**；后续上线非 100% 中奖活动时再拆分
- **行为归属**：加 C / 复购 / 膨胀均以**用户最终选择的实际奖品**对应的行为记录为准；**不单独统计初始奖品与膨胀奖品的归属关系**，避免同一行为重复计数
- **去重规则**：用户类指标按**唯一用户ID**去重；人次类指标按**有效行为记录数**统计
- ⚠️ **模糊指标**：命名模糊的「**首次**」类指标**暂不纳入**正式统计范围（待跑数验证逻辑后再补入体系）
- **费用类**：优先以**微信商户号实际到账**为准，后台中奖记录发放状态做交叉校验；渠道回调延迟/账号异常导致的误差**以第三方最终对账为准，不做人工修正**
- **发放完成判定**：以**用户完成获取动作（加C / 复购 / 直接领取）**为准，**而非后台配置的发放动作**

#### ⑤ 落地安排

- 宽表：活动ID + 奖品属性 + 获取方式 + 膨胀状态 + 用户行为等**全量字段关联为明细宽表** → 统一落 **Hive 数仓**，业务侧可自定义 SQL 查询
- 暂**不做固化看板**（避免指标逻辑未验证导致重复开发，降低迭代与沟通成本）
- 蔡鸿东测试阶段跑数 SQL **可直接复用**（仅需替换表名）
- **校验节点**：7 月底前完成全部指标逻辑**全量验证**，每周同步一次进度；**先 30 人左右样本跑数逐字段核对 → 再对接生产全量数据最终校验**；口径需业务侧负责人确认后再固化看板
- 测试跑数结果（各奖品中奖次数、膨胀行为数据）**符合业务预期**，可直接用于内部汇报；后续**每周更新一次**
