# 01-系统架构总览

> 一物一码（复购红包活动）各子系统职责与边界
>
> 📌 2026-07-28 初版：基于后端技术方案 V26.4.1 整理

## 涉及系统

| 系统 | 职责 |
|:----|:-----|
| **易全五码系统** | 码生成、码分配、码有效性校验（有效/无效/已使用）、码状态同步 |
| **电商促销系统（epromotion）** | 活动配置、奖品配置、抽奖逻辑、扫码校验链 |
| **电商会员系统** | 会员绑定解绑、三方会员同步、历史数据初始化 |
| **微信支付** | 现金红包打款、商户号流水 |
| **企业卡券系统** | 咖啡券采购→发放→核销（最终方案，7/22确认） |
| **C端发券接口** | 原定发券链路（7/22确认不可行，转向企业卡券系统） |

## 扫码校验链

用户扫码后，系统按顺序执行以下校验：

```
扫码触发
  ↓
环境检测     → 是否在合法环境（小程序/APP）
  ↓
活动时间校验 → 是否在活动周期内（半年）
  ↓
登录状态     → 用户是否已登录/授权
  ↓
微信零钱校验 → 现金红包场景下验证零钱账户
  ↓
设备风控     → 设备指纹检测
  ↓
黑名单校验   → 风控黑名单拦截
  ↓
码有效性     → 码状态（有效/无效/已使用）
  ↓
抽奖/发奖
```

## 核心流程

### 1. 复购红包主流程

```
用户首扫码 → 中奖（现金红包/膨胀券）
  ├── 领现金 → 提示"第二瓶扫码后打款"
  └── 膨胀   → 转优惠券（需加C/复购）

用户复购扫码（第二瓶） → 校验码有效性
  ├── 关联首扫码记录
  ├── 请求微信支付（现金红包）
  └── 更新状态（已打款）
```

### 2. 码生命周期

```
码生成（易全）
  ↓
印刷到瓶身（瓶内码/瓶盖外码/箱码）
  ↓
出货/分发
  ↓
用户扫码 → 码有效性校验 → 状态变更为"已使用"
```

### 会员数据通道说明

| 数据源 | 消息通道 | 触发方式 | 处理逻辑 |
|:------|:--------|:--------|:--------|
| **用户行为埋点** | `astrolabe_event_topic` | 用户访问电商页面/扫瓶内码 | 清洗过滤 → 标记来源 → 写入 `emember_topic` |
| **咖啡会员账户变更** | `lucky_member_info_change_topic` | 信息变更 | 解绑/绑定/更新 → 写入 `emember_topic` |
| **咖啡会员手机变更** | `lucky_member_phone_change_for_eorder_topic` | 手机号绑定/换绑/注销 | 解绑/绑定/更新 → 写入 `emember_topic` |
| **三方会员信息** | 定时拉取 | 电商三方服务定期同步 | 投递到 `emember_topic` |

### 事件处理逻辑

所有数据汇聚到 **电商会员 TOPIC (`emember_topic`)** 后，按事件类型分流：

| 事件类型 | 处理逻辑 |
|:--------|:--------|
| **更新事件** | 更新会员基础信息（如头像、昵称、地址） |
| **绑定事件** | 根据手机号关联三方会员和站内会员（合并数据+记录首次来源） |
| **解绑事件** | 解绑站内会员关联关系 |

## 业务全景流程（配置 → 校验 → 中奖）

> 📌 基于 V26.4.1 PRD 总揽流程图（2026-07-29 视觉分析）
>
> 这是统领整个活动的三层流程，串联了运营配置、用户校验、抽奖中奖三个阶段

### 第一层：活动配置流程（运营后台）

```
开始
  ↓
配置活动基本信息
  ↓
配置活动适用范围（产品编码/GS编码）
  ↓
奖品配置
  ↓
奖品发放规则
  ↓
限定城市中奖概率
  ↓
参与活动规则
  ↓
保存活动并启用
  ↓
┌─ GS编码是否有时间重合的活动？
│  ├── 是 → 提示无法启用
│  └── 否 → 保存成功
```

### 第二层：校验流程（用户扫码侧）

```
用户购买 → 扫瓶内码
  ↓
┌─ 是否微信扫码？
│  ├── 否 → 提示「请使用微信扫码」→ 结束
│  └── 是 → ┌─ 链接是否为 n.lkcoffee.com？
│             ├── 否 → 非LK二维码流程
│             └── 是 → 通过链接12位商品编码查询GS编码
│                       ↓
│              ┌─ GS编码是否有效？
│              │  ├── 无效 → 非活动商品 → 返回首页
│              │  └── 有效 → ┌─ 扫码时间是否在活动范围内？
│              │              ├── 否 → ┌─ 活动未开始/已结束弹窗
│              │              │         └── 返回首页
│              │              └── 是 → ┌─ 活动命中情况
│              │                        ├── 活动A → 活动页A
│              │                        ├── 活动B → 活动页B
│              │                        └── 未命中 → 加C专题页
│              │                               ↓
│              │                        ┌─ 是否登录？
│              │                        ├── 是 → 跳转到校验码状态
│              │                        └── 否 →
│              │                              用户隐私保护提示
│              │                              ├── 不同意并退出 → 停留在页
│              │                              └── 同意 → 一键登录
│              │                                       ├── 不登录 → 保持背景页
│              │                                       └── 登录成功
│              │                                              ↓
│              │                                        ┌─ 校验码状态
│              │                                        ├── 30 生产关联 → 感谢品尝/默认奖品
│              │                                        └── 40 出库状态 →
│              │                                                 ↓
│              │                                        ┌─ 二维码是否已使用？
│              │                                        ├── 是 → 提示已使用 → 返回首页
│              │                                        └── 否 →
│              │                                                 ↓
│              │                                        ┌─ 活动是否在有效期内？
│              │                                        ├── 否 → 提示活动已结束
│              │                                        └── 是 → 进入中奖流程
```

### 第三层：中奖流程（抽奖判定）

```
进入中奖流程
  ↓
┌─ L1: 扫码已中奖总量 ≥ 活动奖品总量？
│  ├── 是 → 不中奖（奖品已发光）
│  └── 否 →
│         ↓
┌─ L2: 时段扫码已中奖量 ≥ 时段奖品量？
│  ├── 是 → 不中奖（本时段额度用完）
│  └── 否 →
│         ↓
┌─ L3: 用户扫码次数超上限？
│  ├── 是 → 不中奖
│  └── 否 →
│         ↓
┌─ L4: 用户已中奖量 ≥ 个人上限？
│  ├── 是 → 不中奖
│  └── 否 →
│         ↓
┌─ L5: 是否新用户？
│  ├── 是 → 按配置给X元券（新用户直中）
│  └── 否 → ┌─ 城市中奖量 ≥ 城市奖品量？
│             ├── 是 → 不中奖
│             └── 否 → 按城市中奖概率计算结果
│                       ↓
┌─ 是否配置默认奖项？
│  ├── 是 → 默认奖项（保底）
│  └── 否 → 谢谢参与
```

### 拦截层级

| 层级 | 校验规则 | 失败处理 |
|:---|:--------|:--------|
| **1** | 位置授权校验 | 不中奖 |
| **2** | 活动总库存校验 | 不中奖 |
| **3** | 时间段库存校验 | 不中奖 |
| **4** | 个人中奖上限校验 | 不中奖 |
| **5** | 新用户判定 | **新用户直接中奖**（不走概率） |
| **6** | 城市库存校验 | 不中奖 |
| **7** | 概率计算 | 命中→中奖 / 未命中→不中奖 |

### 概率公式

```
中奖概率 = (城市奖品总量 - 已中奖数) / (城市产品总量 - 已扫码数 / 预估扫码率)
```

| 变量 | 说明 |
|:---|:----|
| 城市奖品总量 | 该城市分配的活动奖品总数 |
| 已中奖数 | 该城市已中奖用户数 |
| 城市产品总量 | 该城市投放的产品总数 |
| 已扫码数 | 该城市已扫码次数 |
| 预估扫码率 | 模型预估的扫码率（用于去除未扫码的沉默产品） |

### 库存模型

| 库存维度 | 说明 |
|:--------|:----|
| **活动总库存** | 全活动级奖品总量，用完后活动停止发奖 |
| **时段库存** | 按时间段（如每天/每小时）分配的奖品量 |
| **城市库存** | 按城市分配的奖品量，动态计算 |
| **个人上限** | 单个用户可中奖次数上限 |

### 门票判定

抽奖前需先通过前置校验链：

```
环境检测 → 活动时间 → 登录状态 → 微信零钱
  → 设备风控 → 黑名单 → 码有效性 → 【7 级抽奖】
```
