# 01-系统架构总览

> 一物一码（复购红包活动）各子系统职责与边界
>
> 📌 2026-07-28 初版：基于后端技术方案 V26.4.1 整理

---

## 涉及系统

| 系统 | 职责 |
|:----|:-----|
| **易全五码系统** | 码生成、码分配、码有效性校验（有效/无效/已使用）、码状态同步 |
| **电商促销系统（epromotion）** | 活动配置、奖品配置、抽奖逻辑、扫码校验链 |
| **电商会员系统** | 会员绑定解绑、三方会员同步、历史数据初始化 |
| **微信支付** | 现金红包打款、商户号流水 |
| **企业卡券系统** | 咖啡券采购→发放→核销（最终方案，7/22确认） |
| **C端发券接口** | 原定发券链路（7/22确认不可行，转向企业卡券系统） |

## 扫码校验链

用户扫码后，系统按顺序执行以下校验：

```
扫码触发
  ↓
环境检测     → 是否在合法环境（小程序/APP）
  ↓
活动时间校验 → 是否在活动周期内（半年）
  ↓
登录状态     → 用户是否已登录/授权
  ↓
微信零钱校验 → 现金红包场景下验证零钱账户
  ↓
设备风控     → 设备指纹检测
  ↓
黑名单校验   → 风控黑名单拦截
  ↓
码有效性     → 码状态（有效/无效/已使用）
  ↓
抽奖/发奖
```

## 核心流程

### 1. 复购红包主流程

```
用户首扫码 → 中奖（现金红包/膨胀券）
  ├── 领现金 → 提示"第二瓶扫码后打款"
  └── 膨胀   → 转优惠券（需加C/复购）

用户复购扫码（第二瓶） → 校验码有效性
  ├── 关联首扫码记录
  ├── 请求微信支付（现金红包）
  └── 更新状态（已打款）
```

### 2. 码生命周期

```
码生成（易全）
  ↓
印刷到瓶身（瓶内码/瓶盖外码/箱码）
  ↓
出货/分发
  ↓
用户扫码 → 码有效性校验 → 状态变更为"已使用"
```

### 3. 会员同步流程

```
电商三方会员表 ←→ 站内会员系统
  ↓
历史数据初始化（涉及大数据历史埋点事件）
  ↓
会员绑定/解绑
```
