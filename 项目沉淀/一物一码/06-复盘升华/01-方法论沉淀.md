## 一、上线管理

### 1. ⭐「上线日」必须拆三层口径（配置上线 / 系统启用 / 商品面客）

- 📌 **实证**：7/16 定 8/1 → 7/17 提 8/4 → 7/20 拆「8/1 配置上线 + 8/5 面客」→ 7/29「原计划明日上线」→ 7/30 系统侧排期（原定晚 6~7 点，**压测拖到凌晨 4~5 点**）→ **8/4 00:00 系统启用（D-Day）** → **8/5 消费者首扫**。索引里「8月1日上线」的旧口径已废弃。
- ✅ **下次**：立项即定义三层 + 每层的「谁宣布 / 什么信号 / 对外怎么说」；**对外只用一个话术，对内分层排期**

### 2. ⭐ 风险清单按「不可逆 × 涉及外部账务」排序，不按物料/设计

- 📌 **实证**：7/26 盯防清单 7 条以物料/设计/客服为主；实际唯一 P0 是**财务打款（8/4 时已 7 天 0 进展）**，靠 B 降级预案「只发券、无需预充值」兜住（8/4 03:35 首巡触发条件）。
- ✅ **下次**：风险表加权重列（不可逆 / 涉外 / 可降级）；**每个涉外项必须配 B 方案 + 触发条件 + 谁有权拍板**

### 3. 值守节奏模板化：6h 一轮战报 + 矛盾识别法

- 📌 **实证**：8/4 四轮战报（03:35 / 09:35 / 15:35 / 21:35）+「**业务侧消停 vs 技术群冒新风险**」矛盾识别法已成型（[[一物一码/01-原始纪要/2026-08-04-D-Day知识沉淀|D-Day 知识沉淀]]）。
- ✅ **下次**：直接复用报送节奏与识别法，不重新设计值守

## 二、活动机制设计

### 4. ⭐「领奖动作」是转化漏斗，不是合规条款——上线前就要给出预期领取率

- 📌 **实证**：v7 规则下**所有奖品**（含 40% 概率的 15 元券）都需 48h 内「加企微 luna」**或**「复购第二瓶」；实测领取率 **8 月 37.6% → 9 月 38.6%**（规模涨 5.3 倍而比率几乎不动）→ 结构性摩擦，**6 成流量在此流失**。
- ✅ **下次**：设计期就为领奖动作定目标值 + 做 A/B（提示时效 / 动作前置 / 失败重试）；**当漏斗管，不当免责声明写**

### 5. 中奖率用「期望人数表」校准，别用直觉判故障

- 📌 **实证**：365 张券 0.0001% → 月期望 **0.18 人**、P(0)=84% → 两月 0 中出**完全正常**（我一度误判为档位失效，经 v7 规则 + 6 档全量反算纠正，实测/期望比 0.98~1.66）。
- ✅ **下次**：拿到规则**先算期望人数表**再判异常；同时评估「宣传语 vs 概率」的数量级落差（期待管理 / 合规）

## 三、数据与归因

### 6. ⭐ 先证伪「运营驱动」，再谈活动效果

- 📌 **实证**：按天曲线与**铺货节点**一一对应（8/9 出库 117 → 8/10 生椰 128 → **8/20→8/21 三口味 1,198→1,540**）；**周末效应≈0**（8 月周末 1,127 vs 工作日 1,036）→ 增长=供给驱动，运营可撬的只有领取率。
- ✅ **下次**：复盘第一步做「供给 vs 需求」归因；**KPI 分母落在供给侧**（铺货量 / 扫码量），避免把铺货涨量记成活动功劳

### 7. 每个「率」都写清分子分母，跨表先做口径表

- 📌 **实证**：发放率反推分母 31,291 vs 选择人数 34,236（差 8.6%）；趋势表参与 33,016 vs 奖品表 34,236（3.7%）；红包「选择 12,852 vs 到账 3,653」。三处对不上 → 结论会被质疑。
- ✅ **下次**：出数前先出一页**口径表**（分子 / 分母 / 去重粒度 / 时间窗 / 数据源），跨表差异逐条给解释

### 8. 成本看「结算单价」，不看面值

- 📌 **实证**：15 元即享券按 **15 元 / 3.3 元 / 0 元**记账，9 月费用差 **40 倍**（140.4 万 vs 33.6 万 vs 3.5 万）→ ROI 根本判不了。
- ✅ **下次**：预算评审即锁定**记账单价 + 结算周期**（N+3 等），复盘全程只用这一个口径

## 四、跨团队推进

### 9. 卡点推进＝单笔样本验证 + 明确归属 + 写死期限

- 📌 **实证**：7/22 财务衔接 → 7/23 用一笔 0.4 元红包（transfer_number 与业务凭证号**尾号 2672 匹配**）验证字段对齐 → 7/24 定位「记账时间在支付系统、不在我方」→ 权责切割、财务后续直连支付侧 → 8/3 因「一元红包」对接叫停 → 8/12、8/14 结算闭环。
- ✅ **下次**：**用一笔真实样本走通全链路**，比开会催有效；同时把「谁负责」写进纪要并定期限

## 五、组织与治理（用户补充 · 2026-10-07 原话）

### 10. ⭐ 一开始就该按「项目制」立治理结构：一个核心负责人 + 各职能子负责人

- 📌 **实证（用户原话）**："如果是在一开始我们有意识的把它当作是一个项目去做推送，有一个核心的项目负责人，然后下面有几个子项目负责人，这样去推动，可能会好一些，比如可以从：**品牌负责人、财务负责人、运营负责人、商业分析负责人**等，这样的视角上去出发，或者去统筹项目会好很多。"
- 🔻 **现实处境（同一原话）**："这里面其实尴尬的地方，是**我在推动财务、技术、以及运营、以及商业分析**"——运营单点横向推 4 个职能，无授权、无资源抓手，全靠个人推动力。
- ✅ **下次**：立项即设「核心项目负责人 + 4 条线子负责人（品牌/财务/运营/商业分析）」，每条线对**同一批上线里程碑**负责、进同一张责任表；核心负责人只做**集成 + 决策 + 对外**，不做逐条推销（对应 [[一物一码/02-业务视角/02-角色责任矩阵\|角色责任矩阵]] 的演进版）。

### 11. ⭐ 关键干系人（财务 VP）必须在方案定稿前进入，否则后期返工改接口

- 📌 **实证（用户原话）**："在一开始的时候，如果**财务 VP 方能够在尽快进入项目中做对齐，那么系统上不会做切换、做改造，变成要重新更换企业系统的接口**等。"——即：晚进入 = 方案返工 + 换企业系统接口（真金白银的工程代价）。
- ✅ **下次**：立项会必到名单＝**品牌 / 财务 / 法务 / 技术 / 数据的一把手（VP 级）**；对任何「会改系统架构/结算链路」的诉求设**准入检查点**——**财务未对齐，不进入开发**（本项目财务线一直拖到 7/22 才衔接、8/3 因「一元红包」被叫停，是同一根因的延续）。

## 六、方案设计期（5/15~6/30）— 第二批

### 12. ⭐ 先锁「唯一北极星指标」，再展开玩法

- 📌 **实证**：5/15 v1 定位"私域引流" → 5/22 会议倾向"品牌曝光 + 参与率" → 5/26 双会明确转为"**加 C 私域运营**"——**11 天内三次翻转**，红包比例、加 C 率、包装三版本（100%中奖 / 888红包 / 全年免费咖啡）全部重估。
- ✅ **下次**：立项会产出「唯一北极星 + 2 个约束指标」的决议单并签字；**北极星未冻结，不准进入奖项比例与包装设计**。

### 13. 多方案用同一张对比表选，不用会议上的"人选"

- 📌 **实证**：5/21 起 6 天内把 v3 量化：**扫码即领参与度高约 12pp、第二瓶复购率高约 6.25pp** → 5/22 据此拍板（四维：参与率/复购率/加C量/交易额）。
- ✅ **下次**：多方案评审材料必须是**同一张多维对比表**（同口径/同参数/同测算周期），没有可比数字不许进决策会。

### 14. 中奖率是「预算参数」，不是「体验参数」

- 📌 **实证**：6/11「第三等奖中奖率从 3% 调至 0.5% 后，**预算从 1000 万左右降至 398 万**」，整体降至 **350 万**。
- ✅ **下次**：预算谈判把**各档中奖率列为可调项清单**；锁定总预算后由运营反推分档中奖率，避免"既要中奖率又要预算"的死结。

### 15. 税负在方案期建模，免税临界点就是预算主旋钮

- 📌 **实证**：6/4 原方案按 9.9 元红包逻辑预算 **956 万**，其中**随机红包税负约 46 万**；因「**4 元以下红包免缴 20% 税负**」，奖项档位需围绕该临界点设计（6/9 专门开税务会）。
- ✅ **下次**：方案模板加「税负敏感度」一页，先锚免税临界点，再排奖项档位；预算表拆「面值成本 + 税负」两行。

### 16. 每个奖品「面值 ≥ 实际履约成本」，杜绝价值倒挂

- 📌 **实证**：5/26「**3.3 元现金饮品券方案成本高，可能导致亏损（咖啡成本约 5.4 元）**」「4 元红包膨胀成咖啡券**价值逻辑不成立**」→ 当场改为 **8.8 咖啡券 + 降中奖概率**。
- ✅ **下次**：方案中每个奖项附「面值 / 物料成本 / 履约成本」三列；**膨胀玩法要单独验算膨胀后档位的价值闭环**。

### 17. 上线前对链路与码做减法

- 📌 **实证**：6/17 关键方案定型——**14 条链路 14 个二维码 → 收敛为 1 个 luna 二维码 + 自动欢迎语 + 单独中奖页面**。
- ✅ **下次**：方案评审强制回答「**能否用 1 个码 / 1 条主链路承载全部玩法**」；做减法优先于做加法。

### 18. 需求的「完成定义」= 目标指标 + MVP 埋点清单

- 📌 **实证**：6/10 黄翠原话「能不能跟我们之前梳理的框架挂上，**每部分的目标是什么、为了提升什么指标**……**埋点也得想想，该提提，别上了之后收集不到数据**」。
- ✅ **下次**：需求评审门禁加两条硬性字段——「本模块目标指标」「埋点清单（事件+参数+口径）」，未填不许排期。

### 19. 合规是排期上的硬门禁，并把「规则锁定期」写进规则

- 📌 **实证**：6/8 法务李晶介入；5/26「法务论证活动规则基本可行，但需**明确约定时间（如三个月），期间规则不能随意更改**」；6/18 交付法务审核稿。
- ✅ **下次**：「规则定稿 + 法务通过」设为**上线前置硬节点**进甘特图；用户可见规则中写明锁定期与变更条款。

### 20. 包装/印刷一改就重走审稿——冻结定稿日 + 预留缓冲

- 📌 **实证**：6/18「包装文件因**去掉一个工厂重提审**，今日发出文稿；量产 **7-17**，入仓 **7-27**」；6/10「主 KV 文案因艺人审核可能调整」。
- ✅ **下次**：包装定稿设独立里程碑并冻结（含工厂清单）；任何文案/工厂变更走**变更单**并重排审稿缓冲。

## 七、冲刺期（7/1~7/26）— 第二批

### 21. ⭐ 上线日锚「包装面市 / 库存到位」，不锚技术完成

- 📌 **实证**：7/9 会议要点要求「先盘线上线下库存，给出最快面市的一物一码产品时间」；7/13 王慧敏「**线上最快替换一物一码包装是 8月22日；线下最快 8.5 左右**」；7/17 定 8/4 → 7/20 改 8/1；7/10「美式本月产程取消，待 8 月排产」。
- ✅ **下次**：立项即把**包装/产线/入仓时间表**作为上线日唯一基准，技术侧倒排。

### 22. 活动规则只写「截止日」，不锁开始时间

- 📌 **实证**：7/9 会议要点「活动上线的时间，在活动规则上，**只写截止日即可，不用锁定开始时间**」（@孙晓伟 @李晶）。
- ✅ **下次**：规则模板默认「活动截止日 + 开始以实际上线为准」；上线日受供给波动时不构成对外违约。

### 23. 艺人物料是关键路径：配置冻结 → 校准规则 → 再提审（串行）

- 📌 **实证**：7/9 定「**技术配置不再改动后校准规则再提审艺人**」；7/17 淼总要求艺人扫码界面「**不要第二次替换**」；7/17 排艺人物料 7/22 提审、7/30 前通过。
- ✅ **下次**：把「配置冻结 → 规则校准 → 物料提审」设为**串行里程碑**，卡在关键路径上单独管。

### 24. 上线前必过一张「异常 / 边界场景清单」

- 📌 **实证**：7/14 陈烈连问：**同一码重复扫能否识别账号**、**单日超 5 次**、**年 300 次上限**、已加过 luna 无领奖链接；7/22 规则写入**设备 id 去重**；7/23 确认非「40 状态」兜底已上线。
- ✅ **下次**：清单固定项＝重复扫/频次上限/设备去重/老用户/扫不出码兜底，**逐项挂负责人与验收时间**。

### 25. 抽奖触发节点选「订单完成」，规避下单套利

- 📌 **实证**：7/6 杨酥提示「支付后到发货完成**用户均可申请退款**；恶意下单赚次数还会拖累下单转化率指标」→ 刘晋泽认可「**只有订单完成会好一点**」，并指出仍可能"点完成→抽奖→退款"。
- ✅ **下次**：次数只在**订单完成**发放，并对「完成即退」设风控观察指标。

### 26. 数据需求必须写明「交付层级」（ODS 不可对外）

- 📌 **实证**：7/3 提数需求只写"同步到 hive"；王东旭回「直接落的表是 **ODS 表，不能直接对外提供**……我得单独建设数仓的中间层」。
- ✅ **下次**：提数模板固定三栏——**源表清单 / 交付层级（业务可用层）/ 口径负责人**，三方确认才排期。
