## 扫码主流程

### 通用扫码入口

```
用户扫码
  ↓
通用扫码接口（epromotion）
  ├── 调用易全码有效性校验 ✅/❌
  ├── 环境检测
  ├── 活动时间校验
  ├── 登录状态校验
  ├── 微信零钱检测（现金红包场景）
  ├── 设备风控
  ├── 黑名单校验
  └── 码有效性校验 → 状态更新
  ↓
返回结果 → 抽奖/提示
```

### 接口示例

```
通用扫码接口:
POST /api/scan
{
  "scanId": "CAP202604300001"
}
```

## 复购红包流程

### 全流程

```
首扫码 → 中奖
  │
  ├── 🟢 领现金
  │     ├── 状态 → LOCKING（待复购）
  │     ├── 预生成权益 ID
  │     └── 等待第二瓶扫码
  │
  ├── 🟢 膨胀券
  │     ├── 状态 → ACTIVE（待使用）
  │     ├── 券已发至券包
  │     └── 可直接下单
  │
  └── 用户购买第二瓶 → 复购扫码
        │
        ├── 调用易全码校验
        ├── 关联首扫码 ID + 预生成权益 ID
        ├── 调用微信支付接口
        │     └── 状态 → PAYING（打款中）
        └── 打款成功 → TRANSFERRED（已到账）
              └── 关联：复购码 ID + 微信商户单号
```

### 奖品发放路径

| 奖品类型 | 发放路径 | 说明 |
|:--------|:--------|:-----|
| **现金红包** | 记录券 → 第二瓶扫码 → 微信打款 | 需二次扫码触发 |
| **咖啡券（立减）** | 转优惠券 → 同步订单号 | 直接发到券包 |
| **咖啡券（满减）** | 转优惠券 → 同步订单号 | 直接发到券包 |
| **膨胀券** | 转优惠券（最终方案：企业卡券系统） | ⚠️ 7/22确认转向企业卡券系统 |

## 状态流转（权益状态机）

### 现金红包状态

```
10 已中奖（INITIAL）
    │  关联：首扫码 ID
    ▼
20 待复购（LOCKING）
    │  关联：首扫码 ID + 预生成权益 ID
    │  用户选择现金 → 权益锁定 → 等待购买第二瓶
    ▼
40 打款中（PAYING）
    │  关联：复购码 ID + 微信商户单号
    │  复购扫码 → 请求微信支付
    ▼
50 已到账（TRANSFERRED）
```

### 膨胀券状态

```
10 已中奖（INITIAL）
    ▼
30 待使用（ACTIVE）
    │  关联：商城优惠券 ID
    │  券已发至券包 → 可直接下单
```

## 系统间依赖关系

### 核心依赖

| 上游系统 | 下游系统 | 依赖类型 | 说明 |
|:--------|:--------|:--------|:-----|
| 用户扫码 | **epromotion**（电商促销） | 黄金流程 | 首扫码 + 复购扫码 |
| epromotion | **易全五码系统** | 强依赖 | 码有效性校验、码状态同步 |
| epromotion | **微信支付** | 强依赖 | 现金红包打款 |
| epromotion | **C端发券接口** | ❌ 已弃用 | 转向企业卡券系统 |
| epromotion | **企业卡券系统** | 🔄 新方案 | 咖啡券采购→发放→核销 |
| epromotion | **电商会员系统** | 强依赖 | 会员绑定/三方同步/历史初始化 |
| epromotion | **大数据埋点** | 依赖 | 活动曝光/参与埋点上报 |

### 强弱依赖校验

| 服务等级 | 说明 | 兜底要求 |
|:--------|:----|:--------|
| L0 服务 | 黄金流程（扫码、抽奖） | 强依赖失败必须有兜底 |
| L2 及以下 | 非核心服务 | L0可依赖L2及以下 |

## API 层规范

| 规范项 | 要求 |
|:------|:-----|
| **限流** | API层默认配置 sentinel 限流熔断 |
| **熔断** | 上下游依赖链路同量级限流策略 |
| **参数校验** | 零信任原则，后端校验所有前端参数 |
| **跨单元调用** | 在 RPC 模块说明 |
| **跨业务域依赖** | 注明非预期依赖 |
