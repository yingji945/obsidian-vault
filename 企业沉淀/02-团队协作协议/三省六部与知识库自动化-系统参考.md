## 一、设计哲学

三省六部不是"我想跑一个 AutoGen 实验"，而是"我需要一个决策系统"。背后的几条原则：

1. **大脑+手脚** — Hermes 做编排大脑，不用自己做所有脏活
2. **圆桌而非并行** — Agent 互相能看到彼此、能反驳、能吵起来，不是各自写报告
3. **角色分界** — 数据大臣只管数据，运营大臣只管业务判断，法务只管合规
4. **每次成长** — 每轮圆桌的结论存下来，下次会前简报

## 二、三省六部角色定义

### 三省（决策层）

| 省 | 角色 | 职责 |
|---|---|---|
| 中书省 | 用户本人 | 最终决策，拍板 |
| 门下省 | 审核大臣（规划中） | 方案复核、风险把关 |
| 尚书省 | 调度大臣（规划中） | 任务协调、进度跟踪 |

### 六部（执行层）

| 部 | 大臣 | 专长 |
|---|---|---|
| 📊 户部 | 数据大臣 | SQL取数、漏斗分析、AB实验、埋点校验 |
| 🎯 礼部 | 运营大臣 | 活动策划、积分商城、用户触达、扫码活动 |
| 🧬 吏部 | 分层大臣 | 用户生命周期、留存分析、沉睡预警 |
| 🔬 工部 | 算法大臣（规划中） | 标签体系、预测模型 |
| ⚖️ 刑部 | 法务大臣 | 合规审查、备案、个税、隐私 |
| 🔍 兵部 | 情报大臣 | 竞品研究、行业动态 |

### 分阶段上线

- **Phase 1 ✅** 数据+运营+法务 3部先跑通

## 四、已确认部署方案

### 运行命令

```bash
PYTHONPATH=~/.local/lib/python3.13/site-packages \
  python3 /opt/data/skills/multi-agent-roundtable/scripts/roundtable_live.py "你的议题"
```

### 已知坑（已全部修复）

| 问题 | 修复 |
|---|---|
| 非OpenAI模型缺少 `model_info` | 显式传 `model_info={"vision":False,...}` |
| Agent名称含中文报错 | 用英文名 + system_message 自我介绍 |
| SelectorGroupChat `{input}` 变量不存在 | 只能用 `{roles}/{participants}/{history}` |
| Selector 重复选同一人 | temperature 降到 0.5 + prompt 加"不要连续选同一个人" |
| 辩论页面无法访问 | 诊断流程：进程→容器→网关→公网IP逐层排查 |

| 📄 链接 | 飞书文档链接 |
| 👤 发送人 | Jacob (cli_aa9fe0a4fa781cb6) |

- 只有老板 @ 才响应，除此以外**绝对静默**
- 包括不主动发"保持安静"——连这条也不发
- **"沉默是一种主动行为"** — 3件不做事 = 主动执行方案B

## 七、制度死亡清单（治理前瞻 · 2026-09-06 · 挂起）

> **状态：挂起。** 触发条件：三省六部**高频使用后**再深扒（三条线：缺位规则设计 / 异质耳目清单 / 制度审计层）。此处先记录清单，防止届时重推。理论背景见 [[个人成长/世界观/我的技术观：重演·排列·跨界]]。

真实唐朝三省六部 = 人类历史上第一次把「跨界制衡」制度化的两百年实验，死因全有档案。**五死法 → 本系统映射**：

| 死法 | 唐朝史实 | 本系统对应 | 自检问题 |
|:--|:--|:--|:--|
| 斜封墨敕 | 嫌门下审核烦，敕令从侧门「斜封」直出，斜封官泛滥 | 嫌圆桌贵/慢，直接在主会话定事 | 绕行率多高？>50% 说明该改革三省，不是更勤快地绕过它 |
| 翰林内相 | 重要诏敕改由内廷翰林起草，「内相」架空外朝宰相 | 圆桌照开，真决定其实早已拍完，agent 只负责补纪要 | 最近一次圆桌**改变**你的决定是什么时候？答不上 = 空转 |
| 使职差遣→藩镇 | 六部僵化后另派使职（盐铁使/节度使），平行系统自成一极反噬中央 | 小灶通道：专属 cron / 单 bot 深聊 / 大臣专属记忆库 | 藩地记忆 vs 中央 vault 谁为准？外部 bot 互不可见 = 藩镇现实版；需定期「朝贡」 |
| 宦官补位 | 皇帝缺位，制衡真空被最近的权力填满 | **cron 自动圆桌无人在场**——那时谁在拍板？selector？终止条件？ | 有无成文缺位规则：无人时只产出建议+分歧，**不产生决定** |
| 台谏党争 | 牛李党争：台谏从监督工具异化成党争武器 | 红队 KPI 就是唱反调，跑久了「反对」本身成为目的 | 红队是「挑刺」还是「逢中必反」？监督者需定期换岗 |

**贞观活着时的边界条件**（制度什么时候有效）：
1. **仲裁者付费**——威慑存在的唯一证据，是你真被大臣拦下过决定且有记录；没被拦过 = 圆桌只是回音壁；
2. **参与者真实异质性**——同源 LLM 底座下，对抗质量上限 = prompt 工程；要给大臣接不同「耳目」（户部真查数/情报真搜索/法务真读文档）——**事权分权 > 角色分权**；
3. **闸门威慑**——门下不是每道敕都驳，存在本身改变行为。对应 token 成本：平时 no_agent/monitor 静默值班（门下守门），文书异动才升堂——**制衡贵在关键处，便宜在平时**。

> 金句：制度是防「人」的，但运行制度也需要「人」——当人觉得被自己的制度防着，就会开始绕。所有死法都是「绕」的艺术，而第一道侧门，往往是制度主人自己开的。三省六部不是死于敌人，是死于「这次就算了」和「直接一点更快」。
> 注脚：连制度的生老病死都在重演——唐朝三省死于这五个病，任何制度化尝试（包括自己的圆桌）不管也会重演；**死亡清单本身就是防腐剂**。
