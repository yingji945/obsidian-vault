## 📄 重点论文

1. 🧠 **Comparative Analysis of Agent Evaluation Frameworks: Stability, Detection, and Discovery in Enterprise Analytics Agents**
   https://arxiv.org/abs/2611.14493
   横向对比企业分析型 Agent 的评测框架，三个维度是**稳定性、检测力、发现力**。对做数据运营的人最实用——它回答的是「怎么判断一个分析 Agent 是真的发现了问题，还是碰巧跑出了数」。

2. 🧠 **ReTrace: Distilling Tool-Using Agents into Planner-Free Workflows**
   https://arxiv.org/abs/2611.14492
   把会调工具的 Agent 蒸馏成不需要 Planner 的固定工作流。工程含义很直接：稳定且高频的任务，最后往往被压回确定性流程，而不是一直留在大模型里。

3. 🤖 **Re-Search: Dissecting LLM Ideation Through a Two-Player Questioning Game**
   https://arxiv.org/abs/2611.14487
   用「双人提问博弈」拆解大模型的创意生成过程，试图把「灵感」拆成可度量的提问策略——评估 LLM 输出质量的一条新路子。

4. 🔬 **Contrastive Discovery: Open-Ended Scientific Discovery over Competing Explanations**
   https://arxiv.org/abs/2611.14514
   让模型同时维护多个「竞争性解释」并做对比式淘汰，而不是一次给出一个答案。科学发现 Agent 从「猜一个」转向「养一批假设」。

5. 🔬 **Precision on Demand: Escalating Weight Bits at Uncertain Decoding Steps in a Small Local Model**
   https://arxiv.org/abs/2611.14418
   只在解码不确定的步上升高权重量化位宽，其余步骤维持低比特。端侧小模型「该省的地方省、该算的地方算」，是成本结构优化里比较干净的一个思路。

## 💡 小编建议

1. **第 1 篇论文可以直接拿来做评测模板**：它把「企业分析 Agent 好不好」拆成稳定性 / 检测力 / 发现力三层。你们做 AB 实验和日常指标归因时，也可以用同一套三问自查——同一个问题问两次答案是否一致（稳定性）、已知异常能否召回（检测力）、没人提示时能否主动指出新问题（发现力）。这比笼统说「Agent 效果不错」更能暴露短板。
2. **「按结果付费」值得提前算一遍**：如果模型厂商真按交付结果计价，现在的「Token 消耗 = 成本」核算方式会失效，成本会跟着业务产出波动而不是跟着调用量走。建议先把自己常用链路的「单次业务动作调用成本」记下来，等计费方式变化时才有基准对比。
3. **GitHub 榜头部被灰产仓库占据**：连续两天出现「API 结算 + 商业 VCC」类仓库，星数不高但标题极具诱导性，涉及绑定支付信息，一律不要点。
